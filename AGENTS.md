# Правила работы AI с проектом X-Buddha

## Перед каждой задачей

Обязательно изучить:

1. `docs/client_tz.md`;
2. `docs/project-plan.md`;
3. `docs/architecture/frontend-prototype.md`;
4. `docs/ui/design-direction.md`;
5. файл текущей задачи в `docs/tasks/`;
6. `PROJECT_RULES.md`;
7. `docs/TODO.md` и `CHANGELOG.md`.

## Порядок работы

1. Сначала проанализировать задачу, действующие требования и текущее состояние кода.
2. Затем выполнить только согласованный объём работ.
3. Проверить результат командами `npm run lint` и `npm run build`.
4. После значимых изменений актуализировать документацию, `docs/TODO.md` и `CHANGELOG.md`.

## Прогресс проекта

- После каждой завершённой задачи читать актуальные work items из `docs/project-plan.md` и обновлять их статусы только по фактически выполненной работе.
- Рассчитывать проценты математически по правилам из `docs/project-plan.md`, не назначать их субъективно и не хранить отдельный набор процентов.
- Последним блоком итогового ответа выводить `ПРОГРЕСС X-BUDDHA` с рассчитанными значениями для всех этапов.
- При изменении состава этапов или work items сначала обновлять `docs/project-plan.md` — единственный источник истины для структуры этапов и расчёта прогресса.

## Постоянные ограничения

- Не изменять и не дополнять требования клиента самостоятельно.
- Не менять архитектуру без отдельного технического задания.
- Не добавлять новые смысловые секции без согласования.
- Не дублировать сведения, уже зафиксированные в профильном документе; вместо этого ссылаться на него.
- Сохранять пользовательские и несвязанные с задачей изменения в рабочем дереве.
