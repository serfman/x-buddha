# Задача 001 — frontend-макет X-Buddha в Codex

## 1. Контекст

Разрабатывается коммерческий сайт X-Buddha — экспертного центра по оценке, атрибуции, экспертизе, выкупу и размещению на аукционе буддийских статуэток и артефактов.

Исходные требования клиента находятся в `client_tz.md`.

До начала работы изучить:

1. `client_tz.md`;
2. `docs/architecture/frontend-prototype.md`;
3. `docs/ui/design-direction.md`;
4. содержимое `public/seed_photos/`.

Если каких-либо изображений ещё нет, реализовать нейтральные локальные заглушки и не использовать изображения из интернета.

## 2. Цель

С нуля создать качественный frontend-макет сайта X-Buddha, который можно показать клиенту и использовать как основу дальнейшей разработки.

На текущем этапе нужен только frontend.

## 3. Обязательный стек

- Next.js 15+;
- App Router;
- TypeScript;
- Tailwind CSS;
- `next/image`;
- React Server Components по умолчанию.

## 4. Запреты

Не создавать и не подключать:

- backend;
- API;
- CMS;
- Directus;
- Supabase;
- БД;
- авторизацию;
- формы;
- загрузку файлов;
- отправку сообщений с сайта;
- внешние изображения;
- тяжёлые animation/UI libraries без необходимости.

Не добавлять новые смысловые секции.

## 5. Работа с изображениями

В `public/seed_photos/`:

- `*slider*` — Hero;
- `*center*` — блок факторов оценки;
- `*footer*` — финальный экран.

Hero-фотографии вертикальные.

## 6. Главная страница

### 6.1 Header

- фиксированный;
- прозрачный в начале;
- после прокрутки получает затемнённый фон и тонкую границу;
- логотип `X-BUDDHA`;
- ссылки: `Оценка`, `Как оценить`, `Статьи`;
- кнопка `Написать`;
- mobile menu.

Создать минималистичный SVG/типографический логотип с акцентом на X.

### 6.2 Hero

Контент:

- визуальная метка: `X-Buddha — экспертный центр`;
- H1: `Оценка и атрибуция буддийских статуэток и артефактов`;
- текст: `Будды, атрибутика и артефакты буддизма.`;
- услуги: `Оценка, выкуп, атрибуция, экспертиза, размещение на аукционе.`;
- три коротких пояснения:
  - `Атрибуция: определение возраста, школы, мастера и культурной ценности.`
  - `Честная оценка: расчёт реальной рыночной и коллекционной стоимости.`
  - `Быстрый выкуп: выплата денег сразу удобным для вас способом.`
- CTA: `Оценить предмет`;
- кнопки Telegram, WhatsApp и MAX.

Desktop:

- текст слева, визуальная сцена справа;
- одновременно три вертикальные фотографии;
- центральное изображение визуально главное;
- плавная автоматическая смена каждые 6 секунд;
- циклическая ротация;
- без свайпа/drag.

Mobile:

- одно изображение;
- автоматическая смена каждые 6 секунд;
- без свайпа, drag и горизонтального скролла;
- текст и CTA должны быть видны без чрезмерно длинного первого экрана.

### 6.3 Факторы оценки

Заголовок:

`Факторы оценки статуэтки`

Вводный текст:

`От чего зависит стоимость вашей фигурки: цена каждого предмета индивидуальна и складывается из множества факторов.`

Факторы:

1. `Время изготовления` — эпоха, век, династия. Указатель в центр постамента.
2. `Место производства` — Тибет, Непал, Китай, Монголия, Бурятия и др. Указатель в область сердца.
3. `Техника и стиль` — бронза, литьё, чеканка, позолота, резьба. Уровень работы: детализация лица, одежды, гравировка. Указатель на узор или декоративную деталь.
4. `Школа и мастер` — авторские клейма, известные мастерские. Указатель на лицо/верхнюю часть.
5. `Размер и вес предмета` — отдельная вертикальная размерная линия.
6. `Состояние` — сохранность патины, наличие дефектов, реставрации. Указатель на руку или область возможной потёртости.

Desktop:

- `center`-изображение в центре;
- подписи слева и справа;
- SVG-линии и точки;
- спокойный космический фон;
- высокая читаемость.

Mobile:

- изображение сверху;
- нумерованные точки;
- список факторов ниже;
- не уменьшать desktop-макет целиком.

### 6.4 Как узнать стоимость

Заголовок:

`Как узнать стоимость прямо сейчас?`

Вводный текст:

`Вам не нужно никуда ехать. Оценка проходит полностью онлайн.`

Шаги:

1. Сделать несколько чётких фотографий с разных ракурсов. Обязательно: основание, лицо, детали крупным планом.
2. Прикрепить фотографии к сообщению и отправить в удобный мессенджер.
3. Написать известную информацию: размеры, вес, история происхождения.

CTA:

`Пишите в сообщения прямо сейчас!`

Дополнительный текст:

`Отвечаю быстро, гарантирую полную конфиденциальность сделки.`

Показать Telegram, WhatsApp и MAX.

Формы и загрузки на сайте отсутствуют.

### 6.5 Видео

- отдельная секция;
- заголовок `Методы оценки бронзовых фигур Азии`;
- 16:9;
- RuTube-ready компонент;
- URL хранится в конфигурации;
- пока возможна заглушка;
- iframe не загружать до клика;
- autoplay запрещён.

### 6.6 Финальный экран

Использовать `footer`-изображение.

Состав:

- атмосферная сцена с тханками/Гималаями;
- логотип X-Buddha;
- Telegram, WhatsApp, MAX;
- ссылки `Статьи`, `Оферта`, `Политика конфиденциальности`;
- `X-Buddha © 2026. Все права защищены.`

## 7. Плавающая связь

На mobile:

- одна фиксированная кнопка `Написать`;
- по нажатию открывается accessible bottom sheet;
- внутри Telegram, WhatsApp и MAX;
- закрытие по кнопке, backdrop и Escape;
- focus trap;
- safe-area.

## 8. Блог

### `/blog`

- заголовок `Статьи`;
- 3–4 mock-статьи;
- обложка, заголовок, анонс, дата;
- без CMS.

Темы mock-статей:

- как определить возраст буддийской статуэтки;
- что влияет на стоимость бронзовой фигуры;
- зачем фотографировать основание предмета;
- особенности тибетских тханок.

### `/blog/[slug]`

- breadcrumbs;
- H1;
- дата;
- обложка;
- текст с H2/H3;
- CTA оценки;
- кнопки мессенджеров;
- ссылка назад.

## 9. Тексты и контент

- основные тексты клиента не переписывать без необходимости;
- не добавлять выдуманную экспертность;
- не добавлять отзывы и кейсы;
- не использовать lorem ipsum;
- mock-тексты блога явно хранить как заменяемый контент.

## 10. Адаптивность

Проверить:

- 360;
- 390;
- 768;
- 1024;
- 1440;
- 1920 px.

Обязательно:

- нет горизонтального скролла;
- CTA не перекрываются;
- fixed-элементы не закрывают контент;
- изображение не деформируется;
- факторы оценки читаются без zoom;
- header и bottom sheet доступны с клавиатуры.

## 11. Дизайн

Следовать `docs/ui/design-direction.md`.

Ключевой принцип: предметы — главные, космос — среда.

Не создавать стандартный SaaS-лендинг с карточками одинаковой формы.

## 12. SEO и metadata

Подготовить уникальные metadata для:

- главной;
- блога;
- статей;
- оферты;
- политики.

## 13. Проверки

До завершения выполнить:

```bash
npm run lint
npm run build
```

Исправить все ошибки и существенные предупреждения.

Проверить вручную:

- маршруты;
- slider rotation;
- отсутствие mobile swipe;
- bottom sheet;
- якорную навигацию;
- reduced motion;
- адаптивность;
- отсутствие внешних изображений;
- отсутствие backend-кода.

## 14. Результат

В конце:

1. кратко описать реализованное;
2. перечислить основные файлы;
3. указать команды запуска;
4. сообщить результаты lint/build;
5. перечислить места, где нужно заменить заглушки: ссылки мессенджеров, RuTube, юридические тексты.
