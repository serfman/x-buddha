# 1. Hero — восстановить акцент «буддийских статуэток»

Текущий H1:

`Оценка и атрибуция буддийских статуэток и артефактов`

Внутри единого H1 слова:

**«буддийских статуэток»**

должны быть главным типографическим акцентом.

Это требование уже было утверждено клиентом и зафиксировано в задаче 003.

Сейчас на production визуальный акцент недостаточно выражен.

Исправить.

## Требования

H1 остаётся одним семантическим `<h1>`.

Использовать внутренние span/типографические стили без разделения заголовка на несколько H1.

«буддийских статуэток» должны быть **явно крупнее окружающей части заголовка**, а не отличаться только цветом или небольшой насыщенностью.

Акцент должен хорошо считываться с первого взгляда.

При этом:

- сохранить премиальную композицию;

- не сделать Hero кричащим;

- сохранить баланс текста и изображений;

- не ухудшить SEO;

- не допустить неестественных переносов.

Использовать responsive typography, например через существующую систему `clamp()` / design tokens, а не случайные фиксированные значения для каждого breakpoint.

# 3. Видео — проблема текущего блока

Сейчас у видеосекции есть три UX-проблемы:

1. в начале блока визуально слишком много пустого пространства;

2. eyebrow `Ролик` выглядит техническим и сухим;

3. до запуска видео пользователь видит почти пустую тёмную область с Play, поэтому видео слабо мотивирует к просмотру.

Исправить эти проблемы.

---

# 4. Новая композиция видеоблока

Поднять смысловую часть секции выше.

На первом экране секции пользователь должен сразу видеть:

- смысловой заголовок;

- короткий контекст;

- визуальный preview видео.

Не оставлять большое пустое пространство над содержимым.

При этом сохранить достаточный air/space и премиальность.

Не делать секцию плотной как обычный контентный блок.

# 5. Название видеоблока

Не использовать пользовательский eyebrow:

`Ролик`

Это техническое название.

Предпочтительный вариант:

Eyebrow:

`ЭКСПЕРТНЫЙ РАЗБОР`

Основной заголовок:

`Как проходит оценка буддийских предметов`

Если после анализа фактического содержания видео эта формулировка ему не соответствует, подобрать более точную формулировку по содержанию ролика.

Не придумывать обещаний, которых нет в видео или `client_tz.md`.

Название должно объяснять пользователю, зачем смотреть видео.

# 6. Preview RuTube

До нажатия Play пользователь должен видеть визуальный preview видео, а не почти полностью чёрный прямоугольник.

Использовать реальный preview/thumbnail RuTube-видео:

`https://rutube.ru/video/2c3be6ec126a5bbb56fe377f14346461/`

Предпочтительный подход:

- получить настоящий thumbnail/preview видео через поддерживаемый RuTube механизм;

- использовать его как poster;

- поверх оставить Play CTA;

- iframe/player загружать лениво только после взаимодействия пользователя, если текущая архитектура это поддерживает.

Не генерировать искусственную обложку.

Не использовать случайный кадр, не относящийся к видео.

Если RuTube предоставляет несколько размеров preview, выбрать достаточный для desktop без загрузки неоправданно большого ресурса.

Добавить лёгкое затемнение/overlay только при необходимости для читаемости Play.
